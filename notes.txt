### versioning in node.js ###

versions are represented like this -> major.recomended.minor
example = 2.3.1, 4.8.4
it has three bits

#starting bit -> represents the major updates any syntactical,symentical update; you should be very consious to update your project on this because their is posibilty that your code may not work on this updatetaion😰.

#middle bit -> it represents the recomended update🎗 you should update your project on this updatation because in this update bugs,and some more functionality are added.

#last bit -> it represent the minor update that are not that much update you can update or not i depends on you

## there are signs like ^,~ before version representation, example = ^4.2.1, ~5.1.3
^ -> it lock the major updatation and automaticaly update the recomended and minor updates
~ -> it lock the major and recomanded update and automaticaly update the minor updatation 

🎡## Restfull APIs ##😴
-> it is nothing but set of the rules that server should follow to called as RestFull APIs Server;
1. client-server architeture -> there is a client and server client req to the server and server responds to that req;
                               -server can send the data as response to the client in json format or html page.
    there are two type of rendering ->  1.SSR(server side rendering)  2.CSR(client side rendering)
    ->in ssr server send the html page to the client the server render the html page itself and then send it to client that can seen on client browser
      -->> ssr are only used when it is sure that client on browser
    
    ->in csr server send the data to the user in json format then client render that data in frontend;
      -->> csr are mostly used when user(client) on mobile or any digital device like alexa

2. respect all the http request methods -> GET, POST, PUT, PATCH, DELETE
   ->> Always use all the req methods according to need;

  GET -> client want to get some data from server
  POST -> client want to send some data to server exmaple -> form
  put -> client want to insert some more data tin his database
  patch => client want to edit or update some data
  delete -> client want to delete some data
